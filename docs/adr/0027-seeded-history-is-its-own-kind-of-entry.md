# ADR-027 — Seeded history is its own kind of entry, built by the same stages.

**Status:** Accepted, 2026-09-29. Builds on ADR-001, ADR-012, ADR-015 and ADR-019.

**Context.** A project that starts logging in O.No months in has a backlog: what people said and did before, in threads, notes and documents. Campbell's is about six months. Efforts written from the live logs alone reads as if the project began the day the guides started logging here, and the clients arrive 2026-09-30. The backlog is compiled by hand in the vault (people's own words, plain noted facts, the documents), and O.No has to take it in without pretending it is anyone's daily log.

**Decision.**
- **A seed is a folder, pushed by a Guide.** Day files `YYYY-MM-DD.md` with `kind: seed`, one `## <Name>` section per person with their words verbatim and a `- src:` line under each group, then `## Noted (not anyone's words)`; `documents/` with `kind: seed-document`, dated and authored; `_people.md` with a role per name. `nopal graphlog seed` posts it to `/api/graphlog/seed`, which writes it into `Syncs/Seed/`, a system folder like `Syncs/Marks/`, each file stamped with its date and content hash so a second push changes nothing. It never touches `Daily Logs/`, a Card, or a mark (`seed.server.ts`).
- **Code splits a day; the model reads it like any day.** sync-graph recognises the Seed folder by id and hands the model one source per section, labelled with who spoke, their role and where the words came from. A spoken section is cited under the person's name with `origin="seed"`, and their human id when the name links to someone on the project. The noted section is cited as "Seed" with `origin="seed-noted"`, never highlighted, with a provenance line in the node's own text (ADR-012), and every noted bullet the model passes over is written verbatim by code, the rule marks follow. The `- src:` lines are provenance, lifted out of the words. No skill file changes: a seed is described to the model in the source label, by code.
- **A name links to an account by exact first name, or stays a name.** `linkSeedNames` matches a section's name against the project's members; two members sharing a first name link to nobody, and it is reported. Seeding never invites anyone or makes an account. The links a day was written with are part of its source hash, so when someone joins later and is put on the project, only the days where they speak re-extract on the next run (ADR-015: a citation's name is baked at write time).
- **Seeded history is the past, not news, and its speakers do not log here.** The readings leave seed nodes out of "since the page was last written", say once how many seeded entries there are and the dates they span, count a noted line as a node and never as a writer, and list in the load picture only seed speakers linked to an account. Every citation into seeded history says so where it is read: the node index, the model's node text, the rendered `:ref`, and the Logbook, where a seed day is pinned under "Seed" with its own badge for the groups that see logs (never a Client).
- **A seed document is a second home for a file** (ADR-019 named one: the Card). It is its own copy: one id serves it, the graph cites it, and a file mark lands on it. Its author is the seed's `author:` line, linked when that name is on the project; its kind is the filing sidecar's, refiled by a person like any file. Costs is where an estimate lands when filed as one; nothing about a Budget is read from it.
- **A wipe removes what the seed alone added.** `/api/graphlog/seed-wipe`, an admin's move (`nopal graphlog seed-wipe --yes`): the Seed folder with everything in it; the graph day files of dates that had no other source; the `sourceHash` of dates that mixed seed and live entries, so the next run rebuilds those from the live entries alone. graph-structure drops the ids that vanished; the Efforts page keeps the seed's words until the next run rewrites it. Cards, `Daily Logs/`, marks and the Budget are never touched, by construction.

**Why it looks removable.** Every seed line could have been a Card written by a Guide at a past date, and the pipeline would have taken it with no new code. It would then be that Guide's daily log, under their name, and every client's words would be theirs: exactly the thing a seed must never be (Austin, 2026-09-29: "never as someone's daily log").

**Limits.** Attachments named in `_attachments.md` are not pushed this round; the CLI prints what it left on disk. The check that a seed does not repeat a live log is a report (which pushed dates already have live entries), not a filter: the folder is cut by hand against the vault, and the intake trusts it. A seed day's citation points at the whole day file, so every section of a day shares one location.

**How you'd know.** A seed line shows as someone's daily log or as today; a noted line carries a person's name or a highlight; "Seed" or an unlinked speaker gets a bench heading; a wipe removes a live day or leaves a seed-only one; a second push doubles anything; a Client reaches a seed day.

**Test.** `webapp/app/tests/graphlog/seed.test.ts`, the seed cases in `effortReadings.test.ts` and `fileFolders.test.ts`, and `fruits/scripts/campbell-walk.ts` (the seeding section) against a running stack.
