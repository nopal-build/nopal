# ADR-018 — The Janitor reports. A person decides.

**Status:** Accepted, 2026-09-18

**Context.** Two people change this repo, from different tools, almost entirely through AI sessions that do not share context, and neither reads every line of what ships. The failure that produced this record: the agent-facing GraphLog skill was rewritten from 1,575 lines to 714 inside a merge commit (`f8c6977`, PR #52) whose message described it as a URL fix. The result was shorter than both parents, so per-file history never showed it, and the person who had written much of that file learned of it two days later. Reading the two versions side by side afterwards, most of the cut was right. That is the point: drift was found and corrected in a single motion, and what reached the other person was a result rather than a diff. The same sweep found the surviving file disagreeing with the code in six places that neither version had caught. The Janitor is the project's standing habit for this: it looks at what it watches from three directions — **form** (is it well formed for whatever loads it), **agreement** (do two statements of one fact still match), **vouching** (has it changed since a person last checked it) — and its first tenants are the runtime skills and the agent skills.

**Decision.** The Janitor reports and never edits. No fix mode, no formatting pass, no tidying on the way past, and no threshold that encodes an opinion (size is shown, never judged; see ADR-017). It is silent when things are clean, because a check that speaks on every run stops being read (ADR-016 says a measurement needs a named reader; this adds that it keeps one only while it is worth reading). So a finding with a confirmable right answer is a failing test (`webapp/app/tests/janitor.test.ts`: a number, tool or field a skill states against the code that holds it; agent skill front matter), green until it is wrong, and what it asks of a person is to pick which side is right. A finding that needs judgment goes in the report (`webapp/scripts/janitor/run.ts`), which today has one kind of line: a watched file changed, with its size before and after, posted on the pull request as a single comment. A new tenant is one more check. Vouching beyond that line (a record of who last validated a skill, keyed on the same fingerprint the stages stamp) is owed once ADR-017's baseline exists; before then a person would have nothing to vouch with and would bump it by reflex.

**Why it looks removable.** Most of what it finds is trivially safe to fix, and an auto-fix looks like pure time saved with no judgment involved. From the other side, a comment that only says a file changed looks redundant with the diff that is already on the pull request, and a test that fails on a reworded sentence looks brittle.

**How you'd know.** A skill changes and nobody sees the diff. The first symptom is output, weeks later, with the cause buried in a commit nobody read. Or the opposite decay: the report grows lines that appear on every pull request, both people stop opening it, and the one line that mattered goes by unread.

**Test.** Nothing under `webapp/scripts/janitor/` has a write path (pinned in `janitor.test.ts`, "has no write path"). Replaying PR #52 (`run.ts --base b50c6ce --head f8c6977`) prints `graphlog/SKILL.md: 1575 -> 714 lines`. On a branch that touches no watched file the report prints nothing.
