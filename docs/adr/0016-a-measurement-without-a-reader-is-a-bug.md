# ADR-016 — A measurement without a named reader is a bug.

**Status:** Accepted, 2026-09-09

**Context.** GraphLog has an unusually disciplined reporting layer: every stage returns `incomplete`, the pipeline aggregates it, the worker persists it to the run row, the run page renders it, and the README wears a banner built from it. That layer was built one wire at a time, each time something failed quietly, and a sweep of the codebase found the same failure sixteen more times in a row. `sync-graph`'s per-day error path logged the failure, recorded it in usage, and then pushed nothing to `incomplete` and nothing to `days` — a rate-limited day vanished and the run badged OK, which is the one thing the field's own doc comment says it exists to prevent. `computeCoverageReport` ran on every clean finish and was read by nothing. `summarizeClusterFields`, written because "nine of ten threads said `active` and nobody knew until a human read the file weeks later," was routed into a job log that expires in twenty-four hours. `error_kind` was classified on every usage row and never selected, so thirty-seven rate-limit errors and thirty-seven oversized images were the same number on the dashboard. The worker persisted exactly three fields from any job result; every other field went to BullMQ's return value, which only the CLI reads and the nightly cron discards. Each of these was correct code that measured the right thing and handed it to nobody.

**Decision.** Every signal a stage computes about its own shortfall reaches a durable surface a person sees, through the same field its other shortfalls use. A stage's error path reports through `incomplete` exactly as its limit paths do; there is no path that logs and moves on. A value on a returned type has a named consumer on the production path (the nightly run and the Vault UI, not only the CLI), or it is removed. `log()` is for a person watching a run live; it is never the only place a finding lands. When code discovers a new thing worth measuring, the first question is who reads it, and the measurement is not done until the answer is a place that outlives the job.

**Why it looks removable.** Logging is easier than persisting, and the log line looks like reporting — the finding is right there in the output, and the run that produced it was watched. A returned field nobody reads looks like a free cleanup, and a `continue` on a failed write looks like graceful degradation. Adding a column, a UI line, and a test for each new signal feels like ceremony around something that already "works". The pattern survives precisely because each instance is small and each looks handled.

**How you'd know.** A run reports OK while a day, a file, a section, or a thread is missing from the output, and the only trace is a container log line or a job log that has already expired. Two very different failures (a rate limit and a bad image; no citations and composed citations) show as the same number. Somebody notices weeks later by reading the file, and the fix is a measurement that already existed.

**Test.** For each stage, an error thrown mid-unit appears in `incomplete` on the run row, not only in the log. Every field on a stage's result type has a consumer on the `"run"` job path, or is gone.
