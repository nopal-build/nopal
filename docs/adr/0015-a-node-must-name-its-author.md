# ADR-015 — A node names its author. Counting people keys on the id, never the name.

**Status:** Accepted, 2026-09-04

**Context.** A node's author is load-bearing in three places at once: the `:ref{}` citation a reader uses to know who said what, the distinct-author union ADR-003 ranks threads by, and the writer count `PROJECT_VIEW.md` hands the model as a constraint before it may claim convergence. All three read the same value, and it silently degraded to a constant. `sync-graph` resolved a contributor's display name out of the local `humans` table and fell through to the literal `"Unknown"` when there was no row; the local pull created exactly one row, the puller's own. So every other contributor became `Unknown`, and they all became the *same* `Unknown`. Nothing errored. Two people ran identical pipeline code against the same project and got wildly different READMEs, and the difference ran backwards from intuition: pulling more people's logs made the output worse, because a one-person pull is accidentally well-conditioned.

**Decision.** A node is never written without a resolvable human author. A candidate carrying a known human id with no named row fails the run, naming the ids; no placeholder is substituted, not even the id itself. A candidate carrying no attribution at all is a different case and is untouched. The citation always carries that person's real name, and every downstream count of "how many people" keys on `authorHumanId`, never on the display name. A name is for reading; an id is for counting.

**Why it looks removable.** `?? "Unknown"` reads as graceful degradation — one contributor is missing from a table, so name them "Unknown" and keep going, because surely a slightly worse citation beats a failed run. That exact move is what produced this failure. It is not degradation, it is a lie that gets written into a permanent file: the name is baked into the node at write time, a node is permanent (ADR-001), and the day's `sourceHash` covers only source file id and content hash — so seeding the missing human afterwards repairs nothing already written, and the day is skipped as up to date on every later run. The graph has to be reset and rebuilt. Failing at write time costs one error message. Re-keying the counts looks removable for a different reason: the id and the name usually agree, so counting names is the same number nearly always, and the ids need a second field to carry. They stop agreeing precisely when someone's identity is missing, which is the case that matters.

**How you'd know.** `name="Unknown"` appears in a `graph-log-*.md` file, or the same person appears under two names, or a README's citations name someone nobody recognizes. Cluster ordering flattens: everyone except one person counts as a single author, so ADR-003's union stops separating convergence from one loud writer and whoever writes most starts winning every ranking. The writers fact reports a number lower than the number of people actually in the project, and a genuinely multi-person graph gets told it is a journal — which suppresses exactly the claims a multi-person tool exists to make. None of this errors, and the README that results reads as complete.

**Test.** Two nodes with different `authorHumanId` and both display names absent count as two distinct authors, not one. A candidate with a known human id and no matching `humans` row raises rather than producing a node, and the error names the id without substituting a placeholder.
